# Config owns the defaults — the bundle comes back total

`resolveBundle` used to return a partial bundle under a stated rule — "resolution never invents" — and every caller substituted its own defaults: the pipeline substituted the template default and the per-provider baseUrl/model defaults, and the setup wizard imported the pipeline's constants to stay in sync. The inventing already happened; it was just scattered across three callers. We decided resolution fills the defaults itself (tagged `source: "default"`) and returns a total bundle, so callers receive values, never absences.

The rule was reopened, not the code around it: the precedence chain (flag > env > config file > repo git-config > global git-config) is unchanged, and the API key still stops at the config file. What moved is only the last step — a key nothing in the chain supplies falls back to the config module's `DEFAULT_*` constants. The baseUrl/model defaults depend on the resolved provider, so provider resolves first inside `resolveBundle`. The `OPENAI_BASE_URL` fallback that the old pipeline carried was dropped outright — it was another tool's ecosystem convention, undocumented here, and a fresh project has no users to keep it for; the documented env path is `COMMITSHI_BASEURL`.
