# Commitshi

A CLI tool that converts the staged changes in a git repo into a concise commit message shaped by the repository's own conventions — generated by a model, then rubber-stamped or edited by a human before the commit happens. Fast, cheap, no wizard, and matches the repo's voice.

## Language

**Commit draft**:
The model-generated commit message, proposed for the user to accept, edit, or discard. It becomes the actual message only after the user confirms.
_Avoid_: "output", "suggestion", "final message"

**Compacted diff**:
The client-side, lossy compressed view of the staged changes — per-file `numstat` plus hunks with unchanged context and trailing lines collapsed — that is what is actually sent to the model. Keeps token cost bounded on large changes without losing change semantics.
_Avoid_: "full diff", "unordered diff", "chunked diff"

**Template**:
The user-authored shape of the commit message, configured as `commitshi.template` in git config. A string of tokens — `{type}`, `{scope}`, `{summary}`, `{body}` — the model fills exactly one value per token.
_Avoid_: "rule", "format string", "schema"

**Staged changes**:
The files the user has `git add`ed — the only input the tool consumes. Unstaged and untracked changes are never part of a commit made by this tool.

**Style history**:
The recent commit subjects the model is shown (last ~8) to pick up the repo's local voice — only when the user opts in with `--style`; never read silently.
_Avoid_: "history context", "commit log sample"
