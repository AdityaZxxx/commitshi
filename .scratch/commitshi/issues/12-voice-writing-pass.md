## Scope (what gets edited, in priority order)

### P0 — Bug-class copy issues

1. **`src/pipeline.ts:91`** — provider-not-supported message. "Anthropic lands in the next ticket" is now wrong (06 was skipped). Rewrite to remove the forward reference and stay honest:
   ```
   commitshi: provider "X" is not supported — commitshi currently understands only the OpenAI-compatible adapter (OpenAI, Groq, DeepSeek, Ollama at any baseUrl).
   ```
   No "yet", no "next ticket", no apology.

2. **`src/loop.ts:180-182`** — the truncation note writes to **stderr** right before the prompt writes to stdout. On a real TTY this scrambles the output if stderr is a different fd (e.g. piped separately in some hooks). Move the note above the draft frame on stdout, or fold it into the draft presentation ticket (13). **For this ticket:** redirect to stdout so it appears with the frame, not split across streams.

3. **`src/loop.ts:216`** — the "press Enter to accept, e to edit..." hint fires on any unknown key. It duplicates the prompt line above and doesn't tell the user what *will happen* on each key. Replace with a one-line re-prompt that uses the same keybinds:
   ```
   commitshi: press Enter to accept, e to edit, r to regenerate, q to quit
   ```
   This is fine, actually — keep the wording, but the duplicate is the issue. Either (a) show the full prompt again on unknown key, or (b) replace with a quiet "unknown key" + repaint prompt. Recommendation: **(b)** — quieter, fewer lines.
